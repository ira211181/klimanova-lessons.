01 · Пояснення

Як працює база даних

Реляційна база даних зберігає відомості у таблицях. Наприклад, у шкільній бібліотеці кожна книжка має свій запис, а поле ID не повторюється.

Поле

Стовпець з одним видом даних: назва, рік, наявність.

Запис

Один рядок про конкретний об’єкт, наприклад книжку.

Первинний ключ

Унікальний ідентифікатор запису, що допомагає уникати плутанини.

Валідація

Перевірка типу, обов’язкових полів, діапазону та унікальності значень.

Запит

Команда для вибірки або зміни даних: SELECT, INSERT, UPDATE, DELETE.

Транзакція

Логічна одиниця змін, яку СУБД може підтвердити або відкотити.

Схема оброблення

Введення → перевірка → збереження → запит → аналіз результату

Приклад SQL

INSERT INTO books (id, title, year)
VALUES (104, 'Майбутнє поруч', 2025);

UPDATE books SET year = 2026
WHERE id = 104;

SELECT title, year FROM books
WHERE year >= 2020
ORDER BY year DESC;

Типова помилка

UPDATE books SET year = 2026; без WHERE може змінити всі записи. Перед масовою зміною створюйте резервну копію.

03 · Практична робота

«Облік шкільних ресурсів»

Мета: створити невелику базу, перевірити дані, додати й відредагувати записи та виконати вибірку. Інструменти: LibreOffice Base / Access або інша навчальна СУБД. У симуляторі нижче можна відпрацювати логіку без встановлення СУБД.

Безпека: не вносьте персональні дані учнів у відкриті навчальні файли; працюйте лише з вигаданими записами. Зберігайте копію перед масовими змінами.
  1. Створіть нову базу SchoolResources і таблицю resources.
  2. Задайте поля id (ціле, ключ), name (текст), year (ціле), available (логічне).
  3. Додайте не менше п’яти вигаданих записів, не повторюючи ID.
  4. Перевірте, що порожня назва й дубльований ключ не приймаються.
  5. Змініть рік одного запису, обов’язково вказавши його ID.
  6. Відберіть доступні ресурси, придбані не раніше 2020 року.
  7. Відсортуйте вибірку за роком у спадному порядку й перевірте результат.
  8. Збережіть файл і коротко поясніть, чому ключ і перевірка даних важливі.

07 · Домашнє завдання

Оберіть рівень практики

Базовий

Створіть таблицю з 5 вигаданими книжками, ID, назвою та роком. Результат: таблиця й скриншот. Критерії: повнота, унікальність ключа, читабельність.

Достатній

Додайте поле наявності, змініть один запис, застосуйте фільтр і поясніть його. Результат: два скриншоти «до/після». Критерії: точність зміни, умова, пояснення.

Високий

Спроєктуйте мінібазу «Шкільний інвентар» із 2 пов’язаними таблицями та ключами. Результат: схема і 2 запити. Критерії: логічність зв’язків, цілісність, перевірка.
